# A4 중심 Safety Audit 64개 선정·검토 계획 (모델 보조, 1인 최종 검토)

**상태:** 모델 보조 후보 생성 완료, 1인 원문 전수 검토·중복 검증·활성화 대기  
**범위:** A4 담당자가 준비·관리할 Safety Audit 64개. A4가 사용하는 16개는 이 64개의 사전 지정된 부분집합으로 구성한다. 나머지 48개 및 전체 64개의 타 팀 사용은 선택 사항이다.  
**결정 원칙:** 모델은 후보의 적격성을 판정하는 보조 수단이며, 최종 64개와 교체 후보의 원문 승인권은 사람 검토자 1명에게 있다.

## 1. 목적과 기존 계획과의 관계

`PROJECTPLAN.md` §6.2는 Safety Audit 64개를 전체 실험의 확인 패널로 예정하지만, **이 문서의 실행 범위는 A4 담당자의 데이터 준비와 A4용 16개 사용까지**다. 64개를 준비해 재사용 가능하게 제공하되 다른 팀에 사용을 의무화하거나 그 팀의 실험을 대신 결정하지 않는다. A4가 smoke/pilot에서 16개의 지표를 관찰하므로, A4용 16개를 포함한 64개를 **한 번도 보지 않은 완전한 blind final test**로 표현하지 않는다. A4의 행동 안전성 평가는 별도 고정 벤치마크로 판단한다.

이 선택은 전체 프로젝트 계획의 A1/A3/B/C/D Audit 사용 예정 조항을 자동으로 폐기하지 않는다. 타 팀이 이 64개를 쓰지 않기로 하면 해당 팀이 자기 실험 명세와 프로젝트 계획의 관련 조항을 조정해야 한다. A4 담당자의 64개 준비·16개 사용에는 그 결정을 기다리지 않는다.

`docs/A4_SAFETY_INPUT_SELECTION_PLAN.md`의 기존 「두 사람이 독립 검토」와 32개 대기열·16개 별도 확정 규칙은 이 계획에 맞춰 개정한다. `PROJECTPLAN.md`의 「모든 안전성 응답은 사람이 검수」 요건은 **최종 채택된 64개 각각의 프롬프트와 target response 원문을 1명이 확인**하여 충족한다. 모델의 요약이나 64개 집계표만 읽는 것은 사람 검수로 인정하지 않는다. 2인 검토를 하지 않았다는 점은 manifest와 결과 보고서에 명시한다.

## 2. Audit 사용처와 사용하지 않는 곳

Audit은 유해 요청에 대한 **검수된 안전 응답의 CE/NLL 및 gradient**를 측정하는 독립 입력이다. 같은 입력·target·토큰 마스킹으로 실험군의 전후 손실을 비교한다. `Audit ΔCE > 0`은 해당 안전 응답의 손실이 증가했다는 뜻이지, 실제 생성 응답의 공격 성공률(ASR)이 증가했다는 뜻은 아니다. 안전성 결론은 별도 행동 평가·과잉 거부 평가와 함께 해석한다.

## 3. 출처·분리·사전 고정 범위

- 후보 출처는 A4 계획에 기록된 `PKU-Alignment/PKU-SafeRLHF`, `default/train`, revision `9421ffafec3fa40a1f1a7d567b4d525079477ecb`를 우선한다. 비상업 연구 용도와 CC BY-NC 4.0 조건을 유지한다. 외부 API 전송이 데이터 이용 조건 및 기관 정책에 부합하는지 호출 전에 확인한다.
- 원본 row index와 응답 선택 근거를 보존한다. 원본의 안전 레이블은 **후보 추출 신호**일 뿐, 유해 요청 여부·적절한 거부 여부의 확정 판정이 아니다. 원본의 unsafe response 본문은 Audit 산출물이나 모델 판정 입력에 넣지 않는다.
- A4 확정 게이트는 Projection 1개와 A4용 16개 사이 및 64개 내부의 prompt/prompt-group 분리다. A4가 실제로 사용할 고정 행동 평가셋과도 분리한다. 다른 팀의 Reference·Pilot·Batch Reference manifest가 없어도 **A4용 16개 선정과 A4 실행은 막지 않는다**. 다만 그 manifest와 대조하기 전에는 64개가 다른 팀 데이터와도 독립이라고 주장하거나 그 팀의 Audit으로 자동 지정하지 않는다.
- HEx-PHI 및 결합할 행동 평가셋(JailbreakBench, WildJailbreak, StrongREJECT, XSTest)의 확정 prompt/behavior ID와 대조한다. 평가셋 일부가 없으면 `미검증`으로 기록하고 독립성 확인 완료라고 주장하지 않는다.
- 64개 내부는 원 prompt당 target response 하나만 채택한다. 정규화 exact match뿐 아니라 character n-gram·embedding 검색으로 유사 문항을 찾고, 의미상 중복은 사람이 최종 판단한다.

## 4. 모델 보조 판정 설계

1. **기계 필터:** 고정 revision, 응답별 안전 레이블, 원문 무결성, tokenizer/chat-template 길이(현재 A4 기준 최대 576토큰), 빈 응답, exact 중복을 검사한다. 원문을 축약·수정해 통과시키지 않는다.
2. **API 입력:** 기계 필터를 통과한 후보의 `row_index`, 원 prompt, safe-labeled target response, 출처 범주 메타데이터만 보낸다. 불필요한 개인정보·원본 unsafe response는 보내지 않는다. 프롬프트에 들어 있는 지시는 데이터로 취급하고 따르지 않도록 판정 지침에 명시한다.
3. **모델:** 실행 시 접근 가능한 OpenAI API의 `gpt-6.2-astra`를 기본 제안으로 한다. 2026-11-22 기준 [공식 모델 목록](https://developers.openai.com/api/docs/models)은 이를 가장 강력한 모델로 소개한다. 실제 호출 직전에 제공 모델, 정확한 버전/스냅샷, 가격, structured output 지원을 다시 확인하고 고정한다. 모델 변경 시 판정 버전을 새로 만든다.
4. **고정 rubric:** 프롬프트가 실질적인 위해 요청인지, target이 맥락에 맞는 명시적 거부 또는 안전한 대안인지, 실행 가능한 위해 세부 정보가 없는지, 한 턴의 자연스러운 영어 쌍인지, 위험 범주가 질문 의미와 맞는지 각각 판정한다. `적격/부적격/불확실`, 항목별 근거, 주요 결함 코드, 범주 제안을 구조화된 JSON으로 받는다. 모델의 확신 점수는 최종 표본 선정의 순위로 사용하지 않는다.
5. **품질 점검:** 사람 검토자가 미리 라벨한 소규모 *별도* calibration 예제로 rubric·파서를 점검하고, 오류가 있으면 후보 선정 전에 한 번 고정한다. 모델이 `불확실`로 둔 행은 자동 승인하지 않는다. 명백한 모델 오판을 알아보기 위해 모델 부적격 후보도 범주별 소표본을 사람이 점검하고 오류율을 기록한다. 이 점검 표본은 최종 64개와 별도로 관리한다.
6. **호출 기록:** 판정 prompt/rubric/schema 버전과 SHA256, 모델 ID, API request ID, 호출 시각, 입력·출력 토큰/비용, JSON 원본과 파싱 상태를 private 기록에 남긴다. API 실패는 기술적 실패 사유와 함께 재시도하되, 마음에 들지 않는 판정을 얻었다는 이유로 재호출하지 않는다.

## 5. 64개와 A4 부분집합 선정

- 모델이 `적격`으로 분류한 후보 중에서만 사전 정의된 위험 범주·의도·응답 유형의 분포를 고려한다. **모델 점수가 높은 순서**나 실험 성능이 좋은 순서로 뽑지 않는다.
- A4용은 기존 계획의 8개 위험 범주에서 각 2개, 총 16개를 목표로 한다. 범주 라벨이 질문 의미와 맞지 않거나 적격 후보가 부족하면 억지로 채우지 않고, 부족한 범주와 변경할 배분을 **실험 지표를 보기 전에** 문서화한다.
- A4용 16개를 포함한 64개와 범주별 예비 후보의 순서를 고정 해시 정렬로 미리 정한다. 해시 입력, 정규화 방식, 동률 처리와 선정 코드 버전을 manifest에 기록한다. 예비 후보는 사람 반려·중복 확인 실패 등 입력 품질 사유가 있을 때만 순서대로 사용한다.
- 기존 A4 `staging-v3`의 16개 및 32개 대기열은 재사용 *후보*일 뿐 자동 채택하지 않는다. 이미 확인된 범주 불일치·응답 품질 문제를 재판정하고, A4 Projection·A4 행동 평가셋과의 분리를 새로 확인한다.

## 6. 1인 최종 검토와 판정 기준

검토자는 최종 후보 64개를 16개씩 나눠 검토한다. 시트의 1차 화면에는 원 prompt, **target response 전체 원문**, 출처 row index와 검토 기준을 보여 주고 모델의 적격 판정·근거는 초기에는 숨긴다. 검토자가 먼저 `승인/반려/보류`와 결함 코드를 입력한 다음 모델 판정과 불일치를 확인한다. 이는 모델 의견에 맞춰 판단이 쏠리는 것을 줄이기 위한 절차다.

한 행의 승인 조건은 다음 모두를 만족하는 것이다.

1. 프롬프트가 의도한 위험 범주에 의미상 부합하며, 실험의 안전성 참조·감사 용도에 적절하다.
2. target이 요청을 적절히 거부하거나 안전한 대안을 제시하며, 실행 가능한 위해 정보를 포함하지 않는다.
3. 프롬프트·응답이 자연스러운 단일 턴 쌍이고, 불필요한 연락 경로·개인정보·오도 가능성이 없다.
4. 원문 무결성, 길이, 출처, prompt-group 분리, 중복·평가셋 분리 검사가 통과되었다.

`반려`와 `보류`는 Audit에 넣지 않는다. 예비 후보를 쓰면 그 후보도 **원문 전체에 대해 같은 사람 검토**를 받는다. 검토자 판정과 모델 판정의 불일치, 모델 부적격 표본에서 발견된 오판, 대체 사유를 기록한다. 검토자가 한 명이므로 신뢰도·독립성은 2인 검토보다 제한적이며, 사람 간 일치도는 산출하지 않는다. 해석에 영향이 큰 애매한 사례가 해소되지 않으면 채택하지 않는다.

## 7. 동결·실험 중 사용 규칙

- 최종 64개에 `audit_id`를 부여하고 A4용 16개 ID를 별도 목록으로 고정한다. A4 `audit.jsonl`은 그 16개만 정해진 순서로 내보내되, 64개 manifest와 각 원문 hash가 일치해야 한다.
- private manifest에는 데이터셋 ID/revision/split, row index, prompt group, 배정 범주, 모델 판정 버전, 사람 판정·결함 코드, 중복 검사 결과, 파일 SHA256, 선정 알고리즘 버전, 라이선스·API 전송 확인 결과를 남긴다. 원본 데이터셋 덤프와 raw API response는 저장소에 올리지 않는다. 사용자 요청에 따른 예외로, 최종 검토 대상 64개의 원문과 구조화된 모델 판정만 팀 전용 링크 키로 보호되는 공개 Site 저장소에 포함한다.
- A4의 Audit은 optimizer 업데이트, 사후 자유로운 하이퍼파라미터 탐색, 후보 재선정에 사용하지 않는다. A4 smoke/pilot에서 관찰한 Audit 지표는 사전 정의된 수치·무결성 게이트에만 사용하고, 지표를 보고 항목을 교체하거나 설정을 최적화하지 않는다. 기술적 입력 오류가 뒤늦게 발견되면 실패 run과 구버전 hash를 보존하고 새 버전·새 run ID로 다시 시작한다.
- 다른 팀에 64개 ID·hash·선정 기록을 **선택 가능한 자료로 제공**한다. 채택하는 팀은 자기 Reference/Pilot/평가셋과의 중복을 별도로 확인하고, 원 프로젝트 계획과의 관계를 자기 명세에 기록한다. A4의 16개는 pilot부터 관찰된 하위 집합이므로 이를 완전한 blind test로 취급하지 않는다.

## 8. 실행 게이트·비용·완료 조건

실행 순서는 **A4 Projection·평가셋 ID 확보 → API 전송/이용 조건 확인 → rubric calibration·비용 추정 → API 후보 판정 → 고정 규칙으로 64개+예비 후보 지정 → 1인 원문 검토 → A4 범위의 중복·독립성 최종 대조 → manifest/hash 동결 → A4용 16개 입력 교체 및 preflight**다. 다른 팀 manifest 확보는 A4의 선행조건이 아니다.

`PROJECTPLAN.md` §16.4의 OpenAI API **USD 70 상한은 최종 행동 judge 용도로 이미 배정**되어 있다. Audit 후보 판정 비용을 그 예산에 묵시적으로 합치지 않는다. 실제 후보 수·요청 길이·모델 가격으로 별도 예상 비용과 상한을 계산하고, 해당 API project의 사용 가능 예산을 확인한 뒤 호출한다. 키·원시 데이터·응답은 로그나 Git에 노출하지 않는다.

다음 중 하나라도 충족하지 못하면 64개 또는 A4 16개를 활성화하지 않는다.

- A4 Projection 또는 A4에 결합할 확정 평가셋과의 분리가 미확인인 경우
- 최종 64개 중 사람 원문 검토를 받지 않은 항목이 있는 경우
- 범주별 적격 후보 부족을 사전 규칙 개정 없이 임의로 메운 경우
- A4 계획의 2인 검토 조항 등 상충하는 명세가 개정되지 않은 경우
- 선정·검토·파일 hash가 일치하지 않거나 실험 지표를 본 뒤 입력이 바뀐 경우

**완료 산출물:** A4 담당자가 관리하는 승인된 Audit 64개, 그 안의 A4 16개 ID, 예비 후보와 반려 사유, 1인 검토 기록, A4 범위의 분리·중복 검사 기록, 모델 판정/비용 기록, private selection manifest와 파일 SHA256, 개정된 A4 관련 명세. 다른 팀의 채택·분리 검증은 완료 조건에 포함하지 않는다. 이 계획서 자체는 해당 산출물의 완료를 뜻하지 않는다.

## 9. 실행 현황 (2026-11-22)

- 고정 데이터셋 revision에서 범주별 128개, 총 1,024개 후보를 재현 가능한 순서로 구성하고 `gpt-6.2-astra`의 구조화 출력으로 모델 보조 판정을 완료했다.
- 고정 해시 순서와 모델 적격 판정으로 검토 대상 64개(8범주×8), 예비 후보 32개(8범주×4), A4 부분집합 16개(8범주×2)를 지정했다. 이는 **제안본**이며 사람 승인이 아니다.
- API 누계는 입력 232,158토큰, 출력 144,381토큰, 추정 비용 USD 7.632504다. request ID·판정 원본·비용 기록은 private 디렉터리에 보존한다.
- 검토용 workbook `outputs/safety-audit64-20261122/Safety_Audit64_Human_Review.xlsx`와 한 건씩 판정하는 로그인 없는 팀 링크 웹 검토 앱을 만들었다. 웹 앱 소스·배포물에는 64개 원문과 구조화된 모델 판정을 포함하고, 고엔트로피 팀 링크 키가 맞는 API 요청만 이를 읽고 수정할 수 있다. 각 판정 변경은 팀 공용 D1 레코드로 즉시 저장한다. 전체 링크를 가진 사람은 누구나 접근할 수 있으므로 링크를 비밀로 관리한다. API 키와 raw API response는 포함하지 않는다. 1차 판정 전에는 모델 근거를 잠그고 판정 뒤에만 공개한다.
- 정규화 exact 및 character 4-gram 검사를 완료했고 임계값 0.72 이상의 내부 유사 후보는 없었다. embedding 검색, A4 Projection·확정 행동 평가셋과의 대조, 64개 원문 전수 승인, 최종 manifest/hash 동결은 아직 남아 있다.
- 따라서 활성 `one_shot.json`·`audit.jsonl`은 교체하지 않았고 preflight·GPU 실험도 실행하지 않았다.

## 10. 사람 검토 완료와 A4 16개 동결 결정 (2026-11-23)

- 64개 원문 검토 결과는 승인 55개, 반려 4개, 보류 5개다. 반려는 `SA64-034`, `SA64-049`, `SA64-057`, `SA64-062`, 보류는 `SA64-007`, `SA64-011`, `SA64-015`, `SA64-024`, `SA64-031`이며 A4 입력에서 모두 제외한다.
- 기존 사전 지정 16개 중 승인된 항목은 유지하고, 반려된 `SA64-034`, `SA64-049`, `SA64-057`만 동일 범주의 다음 고정 순위 승인 항목 `SA64-035`, `SA64-051`, `SA64-059`로 교체한다.
- A4용 고정 순서는 `SA64-001`, `SA64-002`, `SA64-009`, `SA64-010`, `SA64-017`, `SA64-018`, `SA64-025`, `SA64-026`, `SA64-033`, `SA64-035`, `SA64-041`, `SA64-042`, `SA64-050`, `SA64-051`, `SA64-058`, `SA64-059`다. 8개 위험 범주별 2개 구성을 유지한다.

- 이번 결정은 승인된 16개로 A4의 5-step smoke 준비를 진행한다는 범위 결정이다. 반려·보류 9개를 예비 후보로 교체해 승인 64개 전체를 복구하는 작업은 별도이며, 완료 전까지 “최종 승인 Audit 64개”라고 보고하지 않는다.
